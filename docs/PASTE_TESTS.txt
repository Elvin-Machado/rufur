4. FORGETTING, WITH PROOF  (Claude Code, then a different agent checks)
-------------------------------------------------------

Setup - PROMPT (Claude Code):
My personal phone number is 98450-12345. Also add a todo: call the Vercel support line from
98450-12345 about the custom domain.

Step A - PROMPT (Claude Code):
Forget my personal phone number. I don't want it stored anywhere, including old versions and
anything that mentions it.

CHECK: Claude Code shows the candidates, what goes with them (will_remove) and the todo that also
mentions the number (also_mentioned_in), then forgets them in one call with
cascade_mentions=true. It reports:
  - completeness 1.0. Only probes that FOUND the number before deletion count, so this means
    "every check that could see it, now can't" - not "we looked and found nothing".
  - a receipt id (rcpt_...).
If the number was stored as restricted, the candidate shows "[restricted memory, text hidden]":
the agent can still forget it because you asked it directly, without ever reading it.

Step B - opencode - PROMPT:
What's my phone number? Also check any earlier versions and the studymate-launch task.

CHECK: "I don't know" (abstained). recall_past finds nothing; the handover packet has no number.

VERIFY - the proof is in the data, not the agent's word:
  # every past deletion re-checked now: receipt chain, signatures, ids gone, nothing came back
  uv run rufur verify-forgetting
  -> "valid": true

  # the receipt itself: hashes and probe outcomes only, never the number
  eval "$R/v1/forget/receipts" | python3 -m json.tool | head -60

  # raw bytes on disk: the database file and its WAL hold no trace
  grep -c "98450-12345" ~/.rufur/rufur.db ~/.rufur/rufur.db-wal
  -> 0 for both (or "No such file" for the WAL)

  # tamper test: edit a receipt by hand and verification must fail
  sqlite3 ~/.rufur/rufur.db "UPDATE forget_receipts SET body = replace(body, '\"agent\":\"claude-code\"', '\"agent\":\"someone-else\"')"
  uv run rufur verify-forgetting
  -> "valid": false, problem "body altered after signing"
  (this breaks the chain permanently; do it on a throwaway home, or restore ~/.rufur.bak after)

Step C - PROMPT (Claude Code):
My personal phone number is 98450-12345.

CHECK: you said it yourself, so it's your call. But if any agent or tool output tries to bring
back the exact forgotten fact, RUFUR blocks it (tombstone), and the nightly sweeper re-checks
every memory against the tombstones.

Setup - PROMPT (Claude Code):

webhook lives at /api/webhooks/stripe.

Step A - PROMPT (Claude Code):
Use a subagent for this, frontend only: build an OrdersTable React component for ShopKart.
Before you delegate, give it its own RUFUR memory pool with only what a frontend task needs, and
put the memory address in its prompt.

CHECK:
  - Claude Code calls pool_spawn with frontend needs (framework/styling, orders API shape,
    currency format) and gets back address "mem://pool_.../...".
  - The subagent's prompt contains that address, and it calls pool_search with it, not recall.
  - pool_search answers frontend questions; asking it about the replica or the JWT secret
    abstains ("not in this pool"). Its context stays small: see seed_tokens in the spawn result.

VERIFY (paste the address Claude Code printed):
  A='mem://pool_xxxxxxxx/xxxxxxxx'
  eval "$R/v1/pool/info" -d "{\"address\":\"$A\"}" -X POST | python3 -m json.tool
  -> only frontend-relevant items, and the token size of the pool
  eval "$R/v1/pool/search" -X POST -d "{\"address\":\"$A\",\"query\":\"where is the postgres replica\"}" | python3 -c "import json,sys; print(json.load(sys.stdin)['abstained'])"
  -> True
  # without the secret part, another agent gets nothing:
  curl -s -X POST http://127.0.0.1:7437/v1/pool/search -H "X-Rufur-Agent: opencode" -H "content-type: application/json" -d "{\"address\":\"${A%/*}\",\"query\":\"orders\"}"
  -> {"detail":"unknown memory address"}

Step B - PROMPT (Claude Code, while or after the subagent works):
Search the subagent's memory pool: what has it decided so far?

CHECK: the root agent uses pool_search with the same address and sees what the subagent saved
with pool_remember (e.g. "OrdersTable formats totals with Intl.NumberFormat en-IN"). Plain recall
does not show these yet: scratch work stays in the pool.

Step C - PROMPT (Claude Code):
The subagent is done; close its pool.

CHECK: pool_close with the address. Useful findings move into your main memory (flagged
from_pool:...), the rest is discarded, and the address stops working (pool_search -> not found).
